이 옵션은 모듈을 해석하는 방식을 변경 할 수 있습니다. webpack은 알맞은 기본값을 제공하지만, 상세하게 해석 방식을 변경할 수 있습니다. 리졸버의 동작 방식에 대한 자세한 설명은 [Module Resolution](/concepts/module-resolution)을 참고하세요.

## resolve

`object`

모듈 해석에 대한 설정. 예를 들어 ES2015에서 `import 'lodash'`를 호출할 때, `resolve` 옵션은 webpack이 `'lodash'`를 찾는 위치를 변경할 수 있습니다. ([`modules`](#resolvemodules)를 참고하세요).

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    // 설정 옵션
  },
};
```

### Defaults

각 옵션의 시작 기본값입니다. 기본값이 [`target`](/configuration/target/) 또는 모듈 요청 방식에 따라 달라지는 경우, 아래 해당 옵션 섹션에서 정확한 규칙을 설명합니다.

| 옵션                                           | 기본값                                                                         |
| ---------------------------------------------- | ------------------------------------------------------------------------------ |
| [`extensions`](#resolveextensions)             | `['.js', '.json', '.wasm']`                                                    |
| [`mainFiles`](#resolvemainfiles)               | `['index']`                                                                    |
| [`mainFields`](#resolvemainfields)             | web 타겟에서는 `['browser', 'module', 'main']`, 그 외에는 `['module', 'main']` |
| [`aliasFields`](#resolvealiasfields)           | web 타겟에서는 `['browser']`, 그 외에는 `[]`                                   |
| [`modules`](#resolvemodules)                   | `['node_modules']`                                                             |
| [`descriptionFiles`](#resolvedescriptionfiles) | `['package.json']`                                                             |
| [`exportsFields`](#resolveexportsfields)       | `['exports']`                                                                  |
| [`importsFields`](#resolveimportsfields)       | `['imports']`                                                                  |
| [`conditionNames`](#resolveconditionnames)     | `mode`와 `target`에서 파생됩니다. 예: `['webpack', 'production', 'browser']`   |
| [`roots`](#resolveroots)                       | `[context]`                                                                    |
| [`symlinks`](#resolvesymlinks)                 | `true`                                                                         |
| [`preferRelative`](#resolvepreferrelative)     | `false`, `new URL()`과 worker 요청 제외                                        |
| [`preferAbsolute`](#resolvepreferabsolute)     | `false`                                                                        |
| [`enforceExtension`](#resolveenforceextension) | `false`                                                                        |

T> `extensions`, `mainFields`, `aliasFields`, `conditionNames`는 [`resolve.byDependency`](#resolvebydependency)를 통해 디펜던시 타입별로 추가적으로 세분화됩니다. 동일한 패키지에 대한 `require()`와 `import`는 다른 파일로 해석될 수 있습니다. 해당 테이블에 값이 나열되어 있습니다.

### resolve.alias

`object`

`import`나 `require`로 간단히 특정 모듈의 별칭을 만들 수 있습니다. 예를 들어, 일반적으로 사용되는 `src/` 폴더의 별칭을 지정할 수 있습니다.

**webpack.config.js**

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export default {
  // ...
  resolve: {
    alias: {
      Utilities: path.resolve(__dirname, "src/utilities/"),
      Templates: path.resolve(__dirname, "src/templates/"),
    },
  },
};
```

이제 상대 경로를 사용하는 대신 다음과 같이 사용할 수 있습니다.

```js
import Utility from "../../utilities/utility";
```

별칭을 사용할 수 있습니다.

```js
import Utility from "Utilities/utility";
```

뒤에 `$`를 객체의 키에 추가하여 정확하게 일치하도록 할 수 있습니다.

**webpack.config.js**

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export default {
  // ...
  resolve: {
    alias: {
      xyz$: path.resolve(__dirname, "path/to/file.js"),
    },
  },
};
```

결과는 다음과 같습니다.

```js
import Test1 from "xyz"; // 정확한 매칭이므로 path/to/file.js로 해석되어 가져옵니다.
import Test2 from "xyz/file.js"; // 정확한 매칭이 아니고 일반적인 방식으로 가져옵니다.
```

별칭 구성에서 와일드카드(`*`)를 사용하여 더 유연한 매핑을 만들 수도 있습니다.

**webpack.config.js**

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export default {
  // ...
  resolve: {
    alias: {
      "@*": path.resolve(__dirname, "src/*"), // @something을 path/to/something으로 매핑합니다.
    },
  },
};
```

이를 통해 다음과 같은 가져오기를 사용할 수 있습니다.

```js
import Component from "@components/Button";
import utils from "@utils/helpers";
```

다음 표는 다른 사례들을 보여줍니다.

| `alias:`                           | `import 'xyz'`                        | `import 'xyz/file.js'`               |
| ---------------------------------- | ------------------------------------- | ------------------------------------ |
| `{}`                               | `/abc/node_modules/xyz/index.js`      | `/abc/node_modules/xyz/file.js`      |
| `{ xyz: '/abc/path/to/file.js' }`  | `/abc/path/to/file.js`                | error                                |
| `{ xyz$: '/abc/path/to/file.js' }` | `/abc/path/to/file.js`                | `/abc/node_modules/xyz/file.js`      |
| `{ xyz: './dir/file.js' }`         | `/abc/dir/file.js`                    | error                                |
| `{ xyz$: './dir/file.js' }`        | `/abc/dir/file.js`                    | `/abc/node_modules/xyz/file.js`      |
| `{ xyz: '/some/dir' }`             | `/some/dir/index.js`                  | `/some/dir/file.js`                  |
| `{ xyz$: '/some/dir' }`            | `/some/dir/index.js`                  | `/abc/node_modules/xyz/file.js`      |
| `{ xyz: './dir' }`                 | `/abc/dir/index.js`                   | `/abc/dir/file.js`                   |
| `{ xyz: 'modu' }`                  | `/abc/node_modules/modu/index.js`     | `/abc/node_modules/modu/file.js`     |
| `{ xyz$: 'modu' }`                 | `/abc/node_modules/modu/index.js`     | `/abc/node_modules/xyz/file.js`      |
| `{ xyz: 'modu/some/file.js' }`     | `/abc/node_modules/modu/some/file.js` | error                                |
| `{ xyz: 'modu/dir' }`              | `/abc/node_modules/modu/dir/index.js` | `/abc/node_modules/modu/dir/file.js` |
| `{ xyz$: 'modu/dir' }`             | `/abc/node_modules/modu/dir/index.js` | `/abc/node_modules/xyz/file.js`      |

`index.js`가 `package.json`에 정의되어 있으면 다른 파일로 해석될 수 있습니다.

`/abc/node_modules`는 `/node_modules`로 해석될 수 있습니다.

W> `resolve.alias`는 다른 모듈보다 우선하여 해석됩니다.

W> [`null-loader`](https://github.com/webpack-contrib/null-loader)는 webpack 5에서 더 이상 사용되지 않습니다. `alias: { xyz$: false }`나 절대경로 `alias: {[path.resolve(__dirname, './path/to/module')]: false }`를 사용하세요.

W> `string[]` values are supported since webpack 5.

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export default {
  // ...
  resolve: {
    alias: {
      _: [
        path.resolve(__dirname, "src/utilities/"),
        path.resolve(__dirname, "src/templates/"),
      ],
    },
  },
};
```

`resolve.alias`를 `false`로 설정하면 webpack은 모듈을 무시합니다.

```js
export default {
  // ...
  resolve: {
    alias: {
      "ignored-module": false,
      "./ignored-module": false,
    },
  },
};
```

T> 정규 표현식을 기반으로 모듈을 무시하려면 [IgnorePlugin](https://webpack.js.org/plugins/ignore-plugin/)을 사용할 수 있습니다.

### resolve.aliasFields

`(string | string[])[] = ['browser']`

예를 들면 `browser` 같이 [구문](https://github.com/defunctzombie/package-browser-field-spec)을 분석할 필드를 지정합니다.

각 항목은 문자열 배열이 될 수도 있으며, 이는 중첩된 필드 경로를 지정합니다. 예를 들어 `[['exports', 'browser']]`는 `package.json#exports.browser`를 읽습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    aliasFields: ["browser"],
  },
};
```

### resolve.byDependency

모듈 요청의 유형별로 해석 옵션이 설정됩니다.

webpack은 자신이 알고 있는 디펜던시 타입에 대한 기본값을 제공하므로, 같은 요청에 대해 `import`와 `require()`가 다르게 해석될 수 있습니다. `'...'`는 `byDependency` 외부에서 설정된 값을 의미합니다.

| Dependency type                                     | Defaults                                                                                                                                                  |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `esm`, `wasm`, `loaderImport`                       | `conditionNames: ['import', 'module-sync', 'module', '...']`, `mainFields: ['browser', 'module', '...']` on web targets and `['module', '...']` elsewhere |
| `commonjs`, `amd`, `loader`, `unknown`, `undefined` | the same, with `conditionNames: ['require', 'module-sync', 'module', '...']`                                                                              |
| `worker`                                            | as `esm`, with `'worker'` prepended to `conditionNames` and `preferRelative: true`                                                                        |
| `url`                                               | `preferRelative: true`                                                                                                                                    |
| `css-import`                                        | `conditionNames: ['webpack', <mode>, 'style']`, `mainFields: ['style', '...']`, `mainFiles: []`, `extensions: ['.css']`, `preferRelative: true`           |

CSS에서 `mainFiles: []`는 의도적인 설정입니다. CSS `@import`는 디렉터리를 메인 파일로 해석하지 않으므로, 전체 경로를 직접 작성해야 합니다.

- Type: `[type: string]: ResolveOptions`
- Example:

  ```js
  export default {
    // ...
    resolve: {
      byDependency: {
        // ...
        esm: {
          mainFields: ["browser", "module"],
        },
        commonjs: {
          aliasFields: ["browser"],
        },
        url: {
          preferRelative: true,
        },
      },
    },
  };
  ```

### resolve.cache

`boolean`

성공적으로 해결된 요청을 캐싱하여 캐시 항목의 유효성을 다시 검사할 수 있습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    cache: true,
  },
};
```

### resolve.cachePredicate

`(request: ResolveRequest) => boolean`

요청을 캐시할지 여부를 결정하는 함수입니다. 현재 해석 중인 [`ResolveRequest`](https://github.com/webpack/enhanced-resolve)를 인자로 받으며, 이 객체에는 `path`와 `request` 등의 속성이 포함됩니다. 함수는 불리언 값을 반환해야 합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    cachePredicate: (request) =>
      // additional logic
      true,
  },
};
```

### resolve.cacheWithContext

`boolean = true`

unsafe 캐시가 활성화된 경우, 캐시 키에 `request.context`를 포함합니다. 이 옵션은 [`enhanced-resolve`](https://github.com/webpack/enhanced-resolve/) 모듈에서 처리됩니다. `false`로 설정하면 캐시 키에서 컨텍스트가 제외됩니다.

### resolve.conditionNames

`string[]`

패키지의 엔트리 포인트를 정의하는 [`exports` 필드](https://nodejs.org/api/packages.html#packages_exports)의 조건 이름입니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    conditionNames: ["require", "node"],
  },
};
```

Webpack은 `resolve.conditionNames` 배열 내에 나열된 [export 조건](https://nodejs.org/api/packages.html#conditional-exports)과 일치합니다.

#### Default values

기본 `conditionNames`는 [`mode`](/configuration/mode/) 및 [`target`](/configuration/target/) 설정을 기반으로 동적으로 구성됩니다.

기본 조건에는 항상 다음 사항이 포함됩니다.

- `"webpack"`은 항상 존재합니다.
- 현재 [`모드`](/configuration/mode/)에 따라 `"production"` 또는 `"development"`가 선택됩니다. (`"production"`은 모드가 `"none"` 또는 `"production"`일 때 사용됩니다.)

[`대상`](/configuration/target/)에 따라 추가 조건이 추가됩니다.

| 대상 속성   | 상태         |
| ----------- | ------------ |
| `webworker` | `"worker"`   |
| `node`      | `"node"`     |
| `web`       | `"browser"`  |
| `electron`  | `"electron"` |
| `nwjs`      | `"nwjs"`     |

예를 들어 `target: "web"`(기본값) 및 `mode: "production"`인 경우 기본 `conditionNames`는 `["webpack", "production", "browser"]`로 설정됩니다.

#### Per-dependency type conditions

Webpack은 모듈이 임포트되는 방식에 따라 [`resolve.byDependency`](/configuration/resolve/#resolvebydependency)를 통해 `conditionNames`를 추가로 조정합니다. `"..."` 토큰은 위의 기본 조건을 상속합니다.

| 종속성 유형                                         | `conditionNames`                                       | 사용 용도                                 |
| --------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------- |
| `esm`, `wasm`, `loaderImport`                       | `["import", "module-sync", "module", "..."]`           | ESM `import` 문, WebAssembly, 로더 임포트 |
| `commonjs`, `amd`, `loader`, `unknown`, `undefined` | `["require", "module-sync", "module", "..."]`          | `require()` 호출, AMD 및 기타 종속성 유형 |
| `worker`                                            | `["worker", "import", "module-sync", "module", "..."]` | `new Worker()` 표현식                     |
| `css-import`                                        | `["webpack", <mode>, "style"]`                         | CSS `@import` 문                          |

<Badge text="5.107.0+" /> Node.js와의 정렬을 위해 기본 조건에 `"module-sync"`가
포함됩니다. Node.js는 동기적으로 로드 가능한 ESM을 위해 `module-sync` community
condition을 노출하므로, `package.json`에 `module-sync` export를 게시한 패키지는
추가 설정 없이 자동으로 선택됩니다.

예를 들어 `target: "web"` 및 `mode: "production"`인 프로젝트에서 파일이 `import`를 사용하는 경우, 최종적으로 resolve되는 조건은 `["import", "module-sync", "module", "webpack", "production", "browser"]`입니다.

T> `resolveLoader` 옵션은 `conditionNames`에 대해 서로 다른 기본값을 사용합니다. `["loader", "require", "node"]`. [resolveLoader](#resolveloader)를 참고하세요.

#### Condition matching

'수출' 필드의 순서는 매우 중요합니다. 조건 일치 과정에서 먼저 입력된 항목일수록 우선순위가 높으며, 나중에 입력된 항목보다 우선적으로 처리됩니다.

예를들면 다음과 같습니다.

**package.json**

```json
{
  "name": "foo",
  "exports": {
    ".": {
      "import": "./index-import.js",
      "require": "./index-require.js",
      "node": "./index-node.js"
    },
    "./bar": {
      "node": "./bar-node.js",
      "require": "./bar-require.js"
    },
    "./baz": {
      "import": "./baz-import.js",
      "node": "./baz-node.js"
    }
  }
}
```

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    conditionNames: ["require", "node"],
  },
};
```

importing

- `'foo'`는 `'foo/index-require.js'`로 해석됩니다.
- `'foo/bar'`는 `"node"` 키가 조건부 export 객체의 `"require"`키보다 앞에 오기 때문에 `'foo/bar-node.js'`로 해석됩니다.
- `'foo/baz'`는 `'foo/baz-node.js'`로 해석됩니다.

#### Custom conditions

기본 Webpack 값을 유지하면서 사용자 지정 필드 이름을 추가하려면 `"..."`를 사용할 수 있습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    conditionNames: ["my-custom-condition", "..."],
  },
};
```

또는 기본 조건의 우선순위를 먼저 정한 다음 사용자 지정 조건을 추가합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    conditionNames: ["...", "my-custom-condition"],
  },
};
```

### resolve.descriptionFiles

`string[] = ['package.json']`

설명에 사용할 JSON 파일입니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    descriptionFiles: ["package.json"],
  },
};
```

### resolve.enforceExtension

`boolean = false`

`true`로 설정하면 확장자가 없는 파일은 허용되지 않습니다. 따라서 기본적으로 `import foo from "./foo";` 또는 `require('./foo')`는 `./foo` 파일의 확장자가 `.js`인 경우에만 작동하지만, 이 옵션을 활성화하면 `import foo from "./foo.js";` 또는 `require('./foo.js')`만 작동합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    enforceExtension: false,
  },
};
```

### resolve.exportsFields

`string[] = ['exports']`

요청된 모듈을 해석하는데 사용되는 package.json 필드입니다. 자세한 내용은 [package-exports guideline](/guides/package-exports/)를 참고하세요.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    exportsFields: ["exports", "myCompanyExports"],
  },
};
```

### resolve.extensionAlias

`object`

확장자를 확장자 별칭에 매핑하는 객체입니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    extensionAlias: {
      ".js": [".ts", ".js"],
      ".mjs": [".mts", ".mjs"],
    },
  },
};
```

### resolve.extensions

`string[] = ['.js', '.json', '.wasm']`

이러한 확장자를 순서대로 해석합니다. 여러 파일에서 이름이 동일하지만 다른 확장자를 가진 경우, webpack은 배열의 앞에서부터 파일을 해석하고 남은 것은 해석하지 않습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    extensions: [".js", ".json", ".wasm"],
  },
};
```

이는 사용자가 import 할 때 확장자를 생략 할 수 있도록 합니다.

```js
import File from "../path/to/file";
```

위와 같이 `resolve.extensions`를 사용하면 **기본 배열을 재정의** 할 수 있으며, 이는 webpack이 더 이상 기본 확장자를 사용하여 모듈을 해석하지 않습니다. 하지만 `'...'` 을 이용하여 기본 확장자에 접근 할 수 있습니다.

```js
export default {
  // ...
  resolve: {
    extensions: [".ts", "..."],
  },
};
```

### resolve.fallback

`object`

정상적인 확인이 실패하면 모듈 요청을 리디렉션합니다.

**webpack.config.js**

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export default {
  // ...
  resolve: {
    fallback: {
      abc: false, // abc에 대한 폴리필을 포함하지 않습니다.
      xyz: path.resolve(__dirname, "path/to/file.js"), // xyz에 대한 폴리필을 포함합니다.
    },
  },
};
```

Webpack 5는 더 이상 Node.js의 핵심 모듈을 자동으로 폴리필하지 않습니다. 즉, 브라우저 등에서 실행되는 코드에서 사용하는 경우 npm에서 호환되는 모듈을 설치하고 직접 포함해야 합니다. 다음은 webpack 5 이전에 사용한 폴리필 목록입니다.

```js
import { createRequire } from "node:module";

const require = createRequire(import.meta.url);

export default {
  // ...
  resolve: {
    fallback: {
      assert: require.resolve("assert"),
      buffer: require.resolve("buffer"),
      console: require.resolve("console-browserify"),
      constants: require.resolve("constants-browserify"),
      crypto: require.resolve("crypto-browserify"),
      domain: require.resolve("domain-browser"),
      events: require.resolve("events"),
      http: require.resolve("stream-http"),
      https: require.resolve("https-browserify"),
      os: require.resolve("os-browserify/browser"),
      path: require.resolve("path-browserify"),
      punycode: require.resolve("punycode"),
      process: require.resolve("process/browser"),
      querystring: require.resolve("querystring-es3"),
      stream: require.resolve("stream-browserify"),
      string_decoder: require.resolve("string_decoder"),
      sys: require.resolve("util"),
      timers: require.resolve("timers-browserify"),
      tty: require.resolve("tty-browserify"),
      url: require.resolve("url"),
      util: require.resolve("util"),
      vm: require.resolve("vm-browserify"),
      zlib: require.resolve("browserify-zlib"),
    },
  },
};
```

### resolve.fileSystem

`InputFileSystem`

리졸버가 읽는 파일 시스템으로, 기본적으로 컴파일러의 입력 파일 시스템을 사용합니다. 컴파일러의 파일 시스템을 교체하지 않고 다른 파일 시스템(예: 인메모리 파일 시스템)에 대해 해석하도록 설정할 수 있습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    fileSystem: myFileSystem,
  },
};
```

이 옵션은 설정된 리졸버에 속하므로, [`resolveLoader.fileSystem`](#resolveloader)은 로더 해석에 대해 동일하게 동작합니다.

T> 해석 과정만 이 파일 시스템을 통해 처리됩니다. 모듈 소스를 읽는 것은 여전히 컴파일러의 `inputFileSystem`을 통해 이루어지므로, 파일 자체를 제공하는 파일 시스템은 [Node.js API](/api/node/)를 통해 컴파일러에 설정해야 합니다.

```js
import webpack from "webpack";

const compiler = webpack(configuration);

compiler.inputFileSystem = myFileSystem;
```

W> webpack 5.111.0 이전에는 이 옵션이 허용되었지만 무시되었습니다. webpack이 생성하는 모든 리졸버에 컴파일러의 입력 파일 시스템을 덮어써서, 설정한 값이 [enhanced-resolve](https://github.com/webpack/enhanced-resolve)에 전달되지 않았습니다. 해당 버전에서는 위와 같이 `compiler.inputFileSystem`을 설정하거나, 파일 시스템을 기반으로 구성된 전체 [`resolve.resolver`](#resolveresolver)를 제공하세요.

### resolve.fullySpecified

`boolean`

이 옵션을 true로 설정하면 사용자가 지정한 요청을 완전히 지정한 것으로 취급합니다. 즉, 확장자가 자동으로 추가되지 않고 디렉터리 내의 mainFiles도 해석되지 않습니다. 이 동작은 `mainFields`, `aliasFields` 또는 `aliases`를 통해 이루어진 요청에 영향을 미치지 않습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    fullySpecified: true,
  },
};
```

### resolve.importsFields

`string[] = ['imports']`

패키지의 내부 요청에 사용되는 `package.json` 필드입니다. (`#`으로 시작하는 요청은 내부로 간주됩니다).

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    importsFields: ["browser", "module", "main"],
  },
};
```

### resolve.mainFields

`(string | string[])[]`

`import * as D3 from 'd3'`와 같이 npm 패키지를 가져올 때 이 옵션은 `package.json`의 어떤 필드를 검사할 지 결정합니다. 기본값은 webpack 설정에 지정된 [`target`](/concepts/targets)에 따라 달라집니다.

`target` 속성을 `webworker`, `web`이나 설정하지 않은 경우는 다음과 같습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    mainFields: ["browser", "module", "main"],
  },
};
```

다른 target의 경우(`node`포함)

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    mainFields: ["module", "main"],
  },
};
```

예를 들어 다음 필드가 포함된 `package.json`에 있는 `upstream`이라는 임의의 라이브러리를 고려해보세요.

```json
{
  "browser": "build/upstream.js",
  "module": "index"
}
```

`import * as Upstream from 'upstream'`을 실행하면 실제로 `browser` 속성의 파일로 해석됩니다. `browser` 속성은 `mainFields`의 첫 번째 항목이기 때문에 우선하여 해석합니다. 한편, webpack에 의해 번들된 Node.js 애플리케이션은 먼저 `module` 필드의 파일을 사용하여 해석하려고 시도합니다.

### resolve.mainFiles

`string[] = ['index']`

디렉터리를 해석하는 동안 사용할 파일 이름입니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    mainFiles: ["index"],
  },
};
```

### resolve.modules

`string[] = ['node_modules']`

모듈을 해석할 때 검색할 디렉터리를 webpack에 알려줍니다.

절대 경로와 상대 경로를 모두 사용하지만, 약간 다르게 동작 할 수 있습니다.

상대 경로는 Node가 현재 디렉터리와 상위 디렉터리를 통해 `node_modules`를 검색하는 방법과 유사하게 검색됩니다.

절대 경로는 오직 주어진 디렉터리에서만 검색합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    modules: ["node_modules"],
  },
};
```

`node_modules/`보다 우선으로 검색할 디렉터리를 추가하는 것은 다음과 같습니다.

**webpack.config.js**

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export default {
  // ...
  resolve: {
    modules: [path.resolve(__dirname, "src"), "node_modules"],
  },
};
```

### resolve.plugins

[`(Plugin | Function)[]`](/plugins/)

추가로 적용해야 할 해석 플러그인 목록입니다.

각 항목은 다음 중 하나일 수 있습니다.

- `apply(resolver)` 메서드를 가진 플러그인 객체
- 또는 함수 플러그인일 수도 있는데, 이 경우 리졸버가 `this`와 첫 번째 인자로 모두 전달되어 호출됩니다.

이 기능은 [`DirectoryNamedWebpackPlugin`](https://www.npmjs.com/package/directory-named-webpack-plugin)과 같은 플러그인을 허용합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    plugins: [
      // 객체 스타일 플러그인
      {
        apply(resolver) {
          // 사용자 정의 로직
        },
      },

      // 함수형 plugin
      function (resolver) {
        // `this`도 리졸버입니다.
      },
    ],
  },
};
```

`boolean`

<Badge text="5.13.0+" />

해석할 때 [`resolve.roots`](#resolveroots)보다 절대 경로를 선호합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    preferAbsolute: true,
  },
};
```

### resolve.preferRelative

`boolean`

이 옵션을 활성화하면, webpack은 `node_modules` 디렉터리의 모듈을 사용하는 대신 상대적인 요청으로 해석하려 합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    preferRelative: true,
  },
};
```

**src/index.js**

{/* eslint-disable */}

```js
// `src/logo.svg`가 존재한다고 가정해 보세요.
import logo1 from "logo.svg"; // 이것은 `preferRelative`가 활성화되었을 때 가능합니다
import logo2 from "./logo.svg"; // 그렇지 않으면 상대 경로만 사용하여 logo.svg를 해석할 수 있습니다

// `preferRelative` 는 `new URL()` 경우 기본으로 활성화됩니다.
const b = new URL("module/path", import.meta.url);
const a = new URL("./module/path", import.meta.url);
```

### resolve.resolver

`Resolver`

webpack이 자체적으로 구성하는 리졸버 대신 사용할 사전 빌드된 [enhanced-resolve](https://github.com/webpack/enhanced-resolve) `Resolver`입니다. 나머지 `resolve` 옵션은 여전히 적용됩니다. 해당 옵션들이 설명하는 해석 파이프라인은 제공한 인스턴스에 연결됩니다.

인스턴스는 자체 파일 시스템도 가져오며, webpack 5.111.0에서 [`resolve.fileSystem`](#resolvefilesystem)이 지원되기 이전에는 설정에서 다른 파일 시스템을 사용하는 방법이었습니다. 이후로는 파일 시스템만 변경하는 경우에는 `resolve.fileSystem`을 사용하고, 완전히 다른 해석 파이프라인이 필요한 경우에만 전체 리졸버를 사용하세요.

**webpack.config.js**

```js
import { ResolverFactory } from "enhanced-resolve";

export default {
  // ...
  resolve: {
    resolver: ResolverFactory.createResolver({
      fileSystem: myFileSystem,
      extensions: [".js", ".json"],
    }),
  },
};
```

### resolve.roots

`string[]`

서버 상대 URL(`/`로 시작하는 요청)이 해석되는 디렉터리 목록으로, 기본값은 [`context` 설정 옵션](/configuration/entry-context/#context)입니다. 이러한 요청은 먼저 `roots`에 대해 해석되고, 그 다음 절대 경로로 해석됩니다. [`resolve.preferAbsolute`](#resolvepreferabsolute)를 `true`로 설정하면 이 순서를 반대로 할 수 있습니다.

**webpack.config.js**

```js
import path from "node:path";
import { fileURLToPath } from "node:url";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);
const fixtures = path.resolve(__dirname, "fixtures");

export default {
  // ...
  resolve: {
    roots: [__dirname, fixtures],
  },
};
```

### resolve.symlinks

`boolean = true`

심볼릭 링크를 심볼릭 링크된 위치로 해석할지 여부입니다.

활성화되면 심볼릭 링크된 리소스는 심볼릭 링크된 위치가 아닌 _실제_ 경로에서 해석합니다. `npm link`와 같이 패키지를 심볼릭 링크하는 툴로 사용할 때, 모듈 해석이 실패할 수 있습니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    symlinks: true,
  },
};
```

### resolve.unsafeCache

`object` `boolean = false`

모듈에 대한 공격적이지만 **안전하지 않은** 캐싱을 활성화합니다. 설정하지 않으면 비활성화되며, `true`를 전달하면 모든 것을 캐시합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    unsafeCache: true,
  },
};
```

객체가 제공되면 webpack은 이를 캐시로 사용합니다.

예를 들면 일반 객체 대신 [프록시 객체](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy)를 제공할 수 있습니다.

**webpack.config.js**

```js
// 여기 토론에서 복사했습니다 https://github.com/webpack/webpack/discussions/18089
const realUnsafeCache = {};
const unsafeCacheHandler = {
  get(cache, key) {
    const cachedValue = cache[key];

    // 파일이 디스크에 있는지 확인하세요
    if (cachedValue && !fs.existsSync(cachedValue.path)) {
      // 그렇지 않은 경우 해당 캐시 항목을 제거합니다.
      delete cache[key];
      return undefined;
    }

    return cachedValue;
  },
};
const theProxiedCache = new Proxy(realUnsafeCache, unsafeCacheHandler);

export default {
  // ...
  resolve: {
    unsafeCache: theProxiedCache,
  },
};
```

W> 캐시된 경로를 변경하는 것은 간혹 실패의 원인이 될 수 있습니다.

### resolve.tsconfig

<Badge text="5.105.0+" />

`boolean` `string` `object`

TypeScript 경로 매핑 설정입니다. 이 옵션을 사용하면 `tsconfig-paths-webpack-plugin`이 더 이상 필요하지 않습니다. `tsconfig.json` 파일에서 `compilerOptions.baseUrl`과 `compilerOptions.paths`를 읽어와서 가져오기를 해결할 때 해당 별칭을 적용합니다.

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    tsconfig: true, // 기본 tsconfig.json 사용
  },
};
```

**Options:**

- `false` - TypeScript 경로 매핑 비활성화
- `true` - 기본 `tsconfig.json` 파일 사용(자동으로 검색)
- `string` - `tsconfig.json` 파일 경로(상대 경로 또는 절대 경로)

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    tsconfig: "./tsconfig.app.json", // 사용자 지정 경로
  },
};
```

- `object` - `configFile` 및 `references` 옵션을 포함하는 객체

**webpack.config.js**

```js
export default {
  // ...
  resolve: {
    tsconfig: {
      configFile: "./tsconfig.json",
      references: "auto", // 또는 경로 배열
    },
  },
};
```

**Object options:**

- `configFile` (`string`): tsconfig 파일의 경로(상대 경로 또는 절대 경로)
- `references` (`"auto"` | `string[]`): 다른 tsconfig 파일에 대한 참조. `"auto"`는 TypeScript config를 상속하거나 상대/절대 경로 배열을 사용합니다.

**Example tsconfig.json:**

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "components/*": ["src/components/*"]
    }
  }
}
```

그런 다음 코드에서 다음과 같이 작성합니다.

```ts
import Button from "@/components/Button";
import Header from "components/Header";
```

T> 이 옵션은 `resolveLoader`에서도 동일한 구성 옵션으로 사용할 수 있습니다.

## resolveLoader

`{ modules: string[] = ['node_modules'], extensions: string[] = ['.js'], mainFields: (string | string[])[] = ['loader', 'main'], mainFiles: string[] = ['index'], conditionNames: string[] = ['loader', 'require', 'node'], exportsFields: string[] = ['exports'] }`

이 옵션들은 위에 설정된 `resolve` 속성과 동일하지만, webpack의 [loader](/concepts/loaders) 패키지를 해석하는데만 사용됩니다.

**webpack.config.js**

```js
export default {
  // ...
  resolveLoader: {
    modules: ["node_modules"],
    extensions: [".js"],
    mainFields: ["loader", "main"],
  },
};
```

T> 여기서도 alias 및 resolve에서 사용하는 다른 기능을 사용할 수 있습니다. 예를 들어 `{ txt: 'my-text-loader' }`는 `txt!templates/demo.txt`가 `my-text-loader`를 사용하도록 shimming합니다.
