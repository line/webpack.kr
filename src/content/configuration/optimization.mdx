Webpack은 선택된 [`모드`](/configuration/mode/)에 따라 최적화를 실행하기 때문에, 여전히 모든 최적화는 수동 구성 및 재정의에 사용할 수 있습니다.

## optimization.checkWasmTypes

`boolean`

WebAssembly 모듈을 가져오거나 내보낼 때 호환되지 않는 유형의 WebAssembly 모듈을 확인하도록 webpack에 지시합니다.

`optimization.checkWasmTypes`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값  |
| --------------- | ------- |
| `"production"`  | `true`  |
| `"development"` | `false` |
| `"none"`        | `false` |

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    checkWasmTypes: false,
  },
};
```

## optimization.chunkIds

`boolean: false`
`string: 'natural' | 'named' | 'size' | 'total-size' | 'deterministic'`

- `false`: webpack의 내장 청크 ID 알고리즘을 비활성화합니다.
- 다음 값 중 하나:
  - `'natural'`
  - `'named'`
  - `'size'`
  - `'total-size'`
  - `'deterministic'`

Webpack에게 청크 ID에 사용할 알고리즘을 지정합니다. `optimization.chunkIds`를 `false`로 설정하면 Webpack은 내장 알고리즘을 사용하지 않고 플러그인을 통해 사용자 지정 알고리즘을 제공하도록 지시합니다. `optimization.chunkIds`에는 몇 가지 기본값이 있습니다.

`optimization.chunkIds`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값            |
| --------------- | ----------------- |
| `"production"`  | `'deterministic'` |
| `"development"` | `'named'`         |
| `"none"`        | `'natural'`       |

다음 문자열 값이 지원됩니다.

| 옵션              | 설명                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| `'natural'`       | 사용 순서에 따른 숫자 ID입니다.                                                                                |
| `'named'`         | 디버깅을 위한 식별 가능한 ID입니다.                                                                            |
| `'deterministic'` | 컴파일 간에 변경되지 않는 짧은 숫자 ID입니다. 장기 캐싱에 유용합니다. 프로덕션 모드에서 기본으로 활성화됩니다. |
| `'size'`          | 최소 초기 다운로드 크기에 초점을 맞춘 숫자 ID입니다.                                                           |
| `'total-size'`    | 최소 전체 다운로드 크기에 초점을 맞춘 숫자 ID입니다.                                                           |

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    chunkIds: "named",
  },
};
```

기본적으로 `optimization.chunkIds`가` 'deterministic'`으로 설정된 경우 최소 3자리 숫자가 사용됩니다. 기본 동작을 오버라이드하려면 `optimization.chunkIds`를 `false`로 설정하고 `webpack.ids.DeterministicChunkIdsPlugin`을 사용하세요.

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    chunkIds: false,
  },
  plugins: [
    new webpack.ids.DeterministicChunkIdsPlugin({
      maxLength: 5,
    }),
  ],
};
```

## optimization.emitOnErrors

`boolean`

컴파일 중 오류가 발생할 때마다 애셋을 내보내려면 `optimization.emitOnErrors`를 사용하세요. 이렇게 하면 오류가 있는 애셋이 방출됩니다. 심각한 오류는 생성된 코드로 내보내지고 런타임에 오류를 발생시킵니다.

`optimization.emitOnErrors`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값  |
| --------------- | ------- |
| `"production"`  | `false` |
| `"development"` | `true`  |
| `"none"`        | `true`  |

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    emitOnErrors: true,
  },
};
```

W> webpack [CLI](/api/cli/)를 사용한다면, 이 플러그인이 활성화되어있는 동안 webpack 프로세스가 오류 코드와 함께 종료되지 않습니다. CLI를 사용할 때 webpack이 "실패"하게 하려면 [`bail` 옵션](/api/cli/#advanced-options)을 확인하세요.

## optimization.avoidEntryIife

`boolean`

<Badge text="5.95.0+" />

T> IIFE(즉시 실행 함수 표현식)는 생성된 직후 바로 실행되는 함수입니다. webpack은 이를 사용해 코드를 래핑하고 변수 충돌을 방지합니다.

진입 모듈을 IIFE로 감싸야 하는 경우 `optimization.avoidEntryIife`를 사용해 IIFE 래핑을 피할 수 있습니다.([JavascriptModulesPlugin](https://github.com/webpack/webpack/blob/main/lib/javascript/JavascriptModulesPlugin.js)에서 `"This entry needs to be wrapped in an IIFE because"`를 검색해보세요.) 이 접근 방식은 JavaScript 엔진의 성능을 최적화하고 ESM 라이브러리 빌드 시 트리 셰이킹을 가능하게 합니다.

현재 `optimization.avoidEntryIife`는 다른 모듈과 함께 단일 항목 모듈만 최적화할 수 있습니다.

`optimization.avoidEntryIife`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값  |
| --------------- | ------- |
| `"production"`  | `true`  |
| `"development"` | `false` |
| `"none"`        | `false` |

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    avoidEntryIife: true,
  },
};
```

W> `optimization.avoidEntryIife` 옵션은 빌드 성능에 부정적인 영향을 미칠 수 있습니다. 이러한 최적화보다 빌드 성능을 우선시하는 경우 이 옵션을 비활성화하는 것을 고려하십시오.

## optimization.minimizer

`[MinimizerPlugin]` and/or `[function (compiler)]` or `undefined | null | 0 | false | ""`

하나 이상의 사용자 지정 [MinimizerPlugin](/plugins/minimizer-webpack-plugin/) 인스턴스 또는 다른 minimizer를 제공해 기본 minimizer를 재정의할 수 있습니다. webpack 5.87.0부터는 falsy 값을 사용해 특정 minimizer를 조건부로 비활성화할 수도 있습니다.

**webpack.config.js**

```js
import MinimizerPlugin from "minimizer-webpack-plugin";

export default {
  optimization: {
    minimizer: [
      new MinimizerPlugin({
        parallel: true,
        minimizerOptions: {
          // https://github.com/webpack/minimizer-webpack-plugin#minimizeroptions
        },
      }),
    ],
  },
};
```

또는 함수로 제공할 수 있습니다.

```js
import MinimizerPlugin from "minimizer-webpack-plugin";

export default {
  optimization: {
    minimizer: [
      (compiler) => {
        new MinimizerPlugin({
          /* your config */
        }).apply(compiler);
      },
    ],
  },
};
```

기본적으로 webpack은 `optimization.minimizer`를 [다음 값으로](https://github.com/webpack/webpack/blob/4b4ca3bb53f36a5b8fc6bc1bd976ed7af161bd80/lib/config/defaults.js#L1160-L1174) 설정합니다.

```js
import MinimizerPlugin from "minimizer-webpack-plugin";

const minimizer = [
  {
    apply: (compiler) => {
      new MinimizerPlugin({
        minimizerOptions: {
          compress: {
            passes: 2,
          },
        },
      }).apply(compiler);
    },
  },
];
```

`optimization.minimizer`를 사용자 정의할 때 기본 값을 유지하려는 경우 `'...'`로 접근할 수 있습니다.

```js
export default {
  optimization: {
    minimizer: [new CssMinimizer(), "..."],
  },
};
```

기본적으로, `'...'`은 [기본 설정값에 접근하는 지름길](https://github.com/webpack/webpack/blob/4b4ca3bb53f36a5b8fc6bc1bd976ed7af161bd80/lib/config/defaults.js#L98-L108) 입니다. 그렇지 않으면 webpack이 우리를 위해 설정합니다.

## optimization.moduleIds

`boolean: false` `string: 'natural' | 'named' | 'deterministic' | 'size'`

모듈 ID를 선택할 때 사용할 알고리즘을 결정합니다. `optimization.moduleIds`를 `false`로 설정하면, 플러그인을 통해 사용자 정의 알고리즘이 제공될 수 있으므로 내장 알고리즘을 사용해서는 안 된다고 webpack에 알립니다.

`optimization.moduleIds`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값            |
| --------------- | ----------------- |
| `"production"`  | `'deterministic'` |
| `"development"` | `'named'`         |
| `"none"`        | `'natural'`       |

다음 문자열 값이 지원됩니다.

| 옵션            | 설명                                                 |
| --------------- | ---------------------------------------------------- |
| `natural`       | 사용 순서에 따른 숫자 ID입니다.                      |
| `named`         | 디버깅을 위한 식별 가능한 ID입니다.                  |
| `deterministic` | 모듈 이름을 작은 숫자 값으로 해시합니다.             |
| `size`          | 최소 초기 다운로드 크기에 초점을 맞춘 숫자 ID입니다. |

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    moduleIds: "deterministic",
  },
};
```

`deterministic` 옵션은 장기 캐싱에 유용하지만, `hashed` 옵션에 비해 번들 크기가 더 작습니다. 숫자 값의 길이는 ID 공간의 최대 80%를 채우도록 선택됩니다. 기본적으로 `optimization.moduleIds`가 `deterministic`으로 설정된 경우 최소 3자리 숫자가 사용됩니다. 기본 동작을 재정의하려면 `optimization.moduleIds`를 `false`로 설정하고 `webpack.ids.DeterministicModuleIdsPlugin`을 사용하십시오.

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    moduleIds: false,
  },
  plugins: [
    new webpack.ids.DeterministicModuleIdsPlugin({
      maxLength: 5,
    }),
  ],
};
```

W> `moduleIds: 'deterministic'`은 webpack 5에 추가되었으며, 이로 인해 `moduleIds: 'hashed'`는 더 이상 사용되지 않습니다.

W> `moduleIds: total-size`는 webpack 5에서 제거되었습니다.

## optimization.nodeEnv

`boolean: false` `string`

webpack이 `process.env.NODE_ENV`를 주어진 문자열 값으로 설정하도록 합니다. `optimization.nodeEnv`를 `false`로 설정하지 않는 한 [DefinePlugin](/plugins/define-plugin/)을 사용합니다.

`optimization.nodeEnv`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값          |
| --------------- | --------------- |
| `"production"`  | `'production'`  |
| `"development"` | `'development'` |
| `"none"`        | `false`         |

사용 가능한 값은 아래와 같습니다.

- 모든 문자열: `process.env.NODE_ENV`를 설정하는 값입니다.
- false: `process.env.NODE_ENV`값을 수정하거나 설정하지 않습니다.

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    nodeEnv: "production",
  },
};
```

T> [mode](/configuration/mode/)가 `'none'`일 때는 `optimization.nodeEnv`는 `false`가 됩니다.

```js
  },
};
```

## optimization.removeEmptyChunks

`boolean = true`

빈 청크를 감지하고 제거합니다. `optimization.removeEmptyChunks`를 `false`로 설정하면 이 최적화가 비활성화됩니다.

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    removeEmptyChunks: false,
  },
};
```

## optimization.runtimeChunk

`object` `string` `boolean`

`optimization.runtimeChunk`를 `true` 또는 `'multiple'`로 설정하면 런타임만 포함된 추가 청크가 각 엔트리 포인트에 추가됩니다. 이 설정은 다음에 대한 별칭입니다.

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    runtimeChunk: {
      name: (entrypoint) => `runtime~${entrypoint.name}`,
    },
  },
};
```

이 대신 `'single'`값을 설정하면 생성된 모든 청크에서 공유할 런타임 파일을 생성합니다. 이 설정은 다음에 대한 별칭입니다.

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    runtimeChunk: {
      name: "runtime",
    },
  },
};
```

`optimization.runtimeChunk`를 `object`로 설정하면 런타임 청크의 이름 또는 이름 팩토리를 나타내는 `name` 속성만 제공 할 수 있습니다.

기본값은 `false`입니다. 각 엔트리 청크에는 런타임이 포함됩니다.

W> import된 모듈은 각 런타임 청크에서 개별적으로 초기화되므로, 페이지에 복수의 엔트리 포인트를 포함하는 경우 이 동작에 주의해야 합니다. 값을 `single`로 설정하거나 하나의 런타임 인스턴스만 허용하는 다른 설정을 사용할 수 있습니다.

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    runtimeChunk: {
      name: (entrypoint) => `runtimechunk~${entrypoint.name}`,
    },
  },
};
```

## optimization.sideEffects

`boolean` `string: 'flag'`

`package.json`의 [`sideEffects`](https://github.com/webpack/webpack/blob/main/examples/side-effects/README.md) 플래그를 인식합니다. 또는 사이드 이펙트 없음으로 플래그 된 모듈은 export가 사용되지 않을 때 건너뛰도록 합니다.

**package.json**

```json
{
  "name": "awesome npm module",
  "version": "1.0.0",
  "sideEffects": false
}
```

T> `sideEffects`는 npm 모듈의 `package.json` 파일에 있어야 합니다. 큰 모듈이 요구되므로 작업자의 프로젝트 `package.json`에서 `sideEffects`를 `false`로 설정하지 않아도 됩니다.

`optimization.sideEffects`는 [`optimization.providedExports`](#optimizationprovidedexports) 활성화에 의존합니다. 이 디펜던시는 빌드 시간 비용이 들지만, 모듈을 제거하면 코드 생성이 적기 때문에 성능에 긍정적인 영향을 미칩니다. 이 최적화의 효과는 코드 베이스에 따라 다르므로 가능한 성능 향상을 위해 시도해보세요.

`optimization.sideEffects`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값   |
| --------------- | -------- |
| `"production"`  | `true`   |
| `"development"` | `'flag'` |
| `"none"`        | `'flag'` |

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    sideEffects: true,
  },
};
```

수동 플래그만 사용하고 소스 코드를 분석하지 않으려면 아래와 같이 사용하세요.

```js
export default {
  // ...
  optimization: {
    sideEffects: "flag",
  },
};
```

T> `optimization.sideEffects`는 사이드 이펙트가 없는 구문만 포함된 모듈도 사이드 이펙트가 없는 것으로 플래그합니다.

## optimization.splitChunks

`object`

webpack v4+에서는 동적으로 가져온 모듈에 새로운 공통 청크 전략을 바로 사용할 수 있습니다. [SplitChunksPlugin](/plugins/split-chunks-plugin/) 페이지에서 이 동작을 설정할 때 사용 가능한 옵션을 확인해보세요.

## optimization.usedExports

`boolean` `string: 'global'`

각 모듈에서 사용된 export를 확인합니다. 이는 [`optimization.providedExports`](#optimizationprovidedexports)에 의존합니다. `optimization.usedExports`에 의해 수집된 정보는 다른 최적화 또는 코드 생성에 사용됩니다. 즉, 사용하지 않은 export는 생성되지 않으며, 모든 사용이 호환되는 경우 export 이름이 단일 식별자로 변경됩니다.
최소화 도구로 데드 코드 제거 시 이로 인해 사용하지 않은 export를 제거 할 수 있습니다.

`optimization.usedExports`의 기본값은 [`mode`](/configuration/mode/)에 따라 다릅니다.

| 모드            | 기본값  |
| --------------- | ------- |
| `"production"`  | `true`  |
| `"development"` | `false` |
| `"none"`        | `false` |

**webpack.config.js**

```js
export default {
  // ...
  optimization: {
    usedExports: false,
  },
};
```

런타임 당 사용된 export 분석에서 제외하려면 아래와 같이 사용하세요.

```js
export default {
  // ...
  optimization: {
    usedExports: "global",
  },
};
```
