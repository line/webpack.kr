webpack 배포를 위한 릴리스 프로세스는 실제로 매우 간단합니다. 다음 단계를 읽으면, 수행 방법을 명확하게 이해할 수 있습니다.

## Pull Requests

pull requests를 `main`브랜치로 병합할 때, _Create Merge Commit_ 옵션을 선택합니다.

## Releasing

릴리즈는 [changesets](https://github.com/changesets/changesets)로 자동화되어 있습니다:

1. 사용자에게 영향을 미치는 모든 pull request는 `.changeset/`에 버전 증가 수준(`patch`, `minor`, `major`)을 선언하는 [changeset](https://github.com/webpack/webpack/blob/main/.changeset/README.md) 파일을 추가합니다.
2. `main`에 푸시할 때마다 [릴리즈 워크플로우](https://github.com/webpack/webpack/blob/main/.github/workflows/release.yml)가 대기 중인 changeset을 소비하고, `package.json`의 버전을 업데이트하며, `CHANGELOG.md`를 작성하는 `chore(release): new release` pull request를 갱신합니다.
3. 해당 pull request를 병합하면 새 버전이 npm에 배포되고 대응하는 git 태그와 [GitHub 릴리즈](https://github.com/webpack/webpack/releases)가 생성됩니다.

릴리즈를 출시한다는 것은 릴리즈 pull request를 병합하는 것을 의미합니다. 릴리즈 시기(패치 릴리즈는 최대한 빠르게, 마이너 릴리즈는 4주마다)는 [`RELEASE_SCHEDULE.md`](https://github.com/webpack/webpack/blob/main/RELEASE_SCHEDULE.md)에 설명되어 있습니다.
