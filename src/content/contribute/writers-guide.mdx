아래에는 콘텐츠 편집 및 추가에 대해 알아야 할 모든 내용이 포함되어 있습니다. 편집이나 추가를 시작하기 전에 몇 가지 확인하세요. 때때로 가장 어려운 부분은 콘텐츠가 있어야 할 위치를 찾고 콘텐츠가 이미 존재하는지 여부를 결정하는 것입니다.

## Process

1. 글이 링크되어 있다면 관련된 이슈를 확인하세요.
2. `편집`을 누르고 구조를 확장하세요.
3. 변경점들을 Pull Request에 생성하세요.

## YAML Frontmatter

모든 글들은 상단에 [YAML Frontmatter](https://jekyllrb.com/docs/frontmatter/)로 쓰인 작은 섹션을 포함합니다.

```yaml
---
title: My Article
group: My Sub-Section
sort: 3
contributors:
  - [github username]
related:
  - title: Title of Related Article
    url: [url of related article]
---
```

각각에 대해 알아보겠습니다.

- `title`: 글의 제목입니다.
- `group`: 하위 섹션의 제목입니다.
- `sort`: 해당 섹션 (또는) 하위 섹션 내에서 글의 순서입니다.
- `contributors`: 글에 기여한 사람들이 GitHub username 리스트입니다.
- `related`: 관련된 읽을거리 또는 유용한 예시입니다.

`related`는 페이지 하단에 **Further Reading** 섹션을 생성하고 `contributors`는 그 아래에 **Contributors** 섹션을 생성합니다. 글을 편집하고 인정받고 싶다면 주저하지 말고 GitHub 사용자 이름을 `contributors` 목록에 추가하세요.

## Article Structure

1. 간략한 소개 - 어떤 것을 왜 하였는지에 대한 아이디어를 적은 한두 문단입니다.
2. 남은 콘텐츠 개요 – 콘텐츠가 표시되는 방식입니다.
3. 주요 콘텐츠 - 주요 내용들을 말하세요.
4. 결론 - 내용들을 정리하고 주요 포인트들을 요약합니다.

## Typesetting

- 문장 시작에서는 Webpack을 대문자 W로 작성할 수 있습니다. ([출처](https://github.com/webpack/media#name))
- loader는 backtick으로 감싸고 [kebab-case](https://en.wikipedia.org/w/index.php?title=Kebab_case)로 작성합니다: `sass-loader`, `ts-loader` 등
- plugin은 backtick으로 감싸고 [camel-case](https://en.wikipedia.org/wiki/Camel_case)로 작성합니다: `BannerPlugin`, `NpmInstallWebpackPlugin` 등
- 특정 webpack 버전은 "webpack 2"로 표기합니다(~~"webpack v2"~~).
- ECMAScript 표준은 ES5, ES2015, ES2016 등으로 표기합니다(~~ES6~~, ~~ES7~~).

## Formatting

### Code

**Syntax: \`\`\`js … \`\`\`**

```js
function foo() {
  return "bar";
}

foo();
```

#### Quotation

코드 스니펫과 프로젝트 파일(`.jsx`, `.scss` 등)에 작은따옴표를 사용하세요.

```diff
- import webpack from "webpack";
+ import webpack from 'webpack';
```

그리고 아래는 인라인 백틱 안에서의 예시입니다.

**correct**

값을 `'index.md'`로 설정...

**incorrect**

값을 `"index.md"`로 설정...

### Assumptions and simplicity

문서를 작성할 때 가정하지 마세요.

```diff
- 프로덕션을 위해 번들을 최적화하는 방법을 이미 알고 있을 수 있습니다...
+ 이미 우리는 [프로덕션 가이드](/guides/production/)에서 배웠습니다...
```

모든 것이 단순하다고 가정하지 마세요. '그냥', '간단하게'와 같은 단어를 피하세요.

```diff
- 간단히 명령을 실행하세요...
+ `command-name` 명령을 실행하세요...
```

### Configuration defaults and types

문서를 쉽게 이해할 수 있고 잘 작성할 수 있도록, 항상 모든 문서 옵션에 유형과 기본값을 제공하세요. 유형은 **TypeScript 표기법**으로 작성하며, 문서화된 옵션 제목 바로 아래에 배치합니다:

**configuration.example.option**

`'none' | 'development' | 'production' = 'none'`

유형이 먼저 오고, 기본값이 있는 경우 `=` 뒤에 따라옵니다. TypeScript에는 기본값 문법이 없으므로, `= value` 형식은 이 사이트가 추가한 유일한 확장입니다. 그 왼쪽의 모든 내용은 편집기에 붙여넣을 수 있는 표준 TypeScript입니다.

단일 유니온보다 구분하기 쉬운 여러 항목을 나열할 때는 어노테이션 사이에 공백을 사용하세요:

`'none' | 'development' | 'production' = 'none'` `boolean`

배열, 함수, 객체, 레코드는 TypeScript 문법 그대로 작성합니다:

| 의미                             | 표기법                                                  |                    |                               |
| -------------------------------- | ------------------------------------------------------- | ------------------ | ----------------------------- |
| 문자열 배열                      | `string[]`                                              |                    |                               |
| 여러 유형이 혼합된 배열          | `(string \| RegExp \| ((arg: string) => string))[]` |
| 인수가 알려진 함수               | `(compilation: Compilation, module: Module) => boolean` |                    |                               |
| 알려진 속성을 가진 객체          | `{ prop1: string, prop2?: boolean }`                    |                    |                               |
| 사용자 정의 키를 가진 객체       | `Record<string, string>`                                |                    |                               |
| 하나 또는 여러 플러그인 인스턴스 | `MinimizerPlugin \| MinimizerPlugin[]` |                               |
| 고정된 숫자 집합                 | `5 \| 15 \| 30 = 15`                      |

선택적 속성은 TypeScript에서 그러하듯이 `?`로 표시하고, 설명 텍스트로 기술하지 마세요.

W> 배열을 `[string]`으로 작성하지 마세요. TypeScript에서 이것은 **정확히 하나의 문자열로 이루어진 튜플**이므로, 언어를 아는 독자는 해당 옵션이 받아들이지 않는 타입으로 읽을 것입니다. `string[]`을 사용하세요.

T> 유형을 직접 만들기보다 실제 유형을 복사하는 것이 좋습니다. webpack은 `lib/`의 JSDoc에서 생성된 자체 타입을 `types.d.ts`로 제공하므로, 옵션의 공식적인 형태는 이미 정의되어 있습니다. `webpack.Configuration`과 그 하위 옵션 인터페이스가 사용자의 편집기에 표시되는 내용입니다. 실제 타입이 너무 복잡한 경우 가독성을 위해 단순화하되, 유효한 TypeScript를 유지하세요.

옵션의 기본값이 [`모드`](/configuration/mode/)에 따라 다를 경우, inline `= 값` 구문 대신 기본값 테이블을 사용하십시오.

**configuration.example.option**

`'natural' | 'named' | 'deterministic'`

`configuration.example.option`의 기본값은 [`mode`](/configuration/mode/)에 따라 달라집니다.

| 모드            | 기본값            |
| --------------- | ----------------- |
| `"production"`  | `'deterministic'` |
| `"development"` | `'named'`         |
| `"none"`        | `'natural'`       |

옵션의 boolean 기본값이 mode에 따라 달라지는 경우:

**configuration.example.flag**

`boolean`

`configuration.example.flag`의 기본값은 [`mode`](/configuration/mode/)에 따라 달라집니다.

| 모드            | 기본값  |
| --------------- | ------- |
| `"production"`  | `true`  |
| `"development"` | `false` |
| `"none"`        | `false` |

### Options shortlists and their typing

때때로 목록에 있는 객체와 함수의 특정 속성을 설명하고 싶을 때가 있습니다. 해당하는 경우, 동일한 TypeScript 표기법으로 속성이 나열된 목록에 직접 유형을 추가합니다:

- `madeUp` (`boolean = true`): short description
- `shortText` (`string = 'i am text'`): another short description
- `pattern` (`RegExp | string`): a property with no default

W> `:`는 여기에서 필수가 아닙니다. 속성, 유형 및 기본값에 유의하세요.

예제는 [EvalSourceMapDevToolPlugin 페이지의 `options` 섹션](/plugins/eval-source-map-dev-tool-plugin/#options)에서 찾을 수 있습니다.

### Adding links

절대적 URL(예: `https://webpack.js.org/concepts/mode/`) 대신 상대적 URL(예: `/concepts/mode/`)을 사용하여 자체 콘텐츠를 연결하세요.
